Implementation plan · 2026-07-10 · xtext · spec B · site + Mac mini worker

Web-paid inscription behind /text

Ten tasks. The surface moves to its platform-neutral home, the directory answers “who uploaded?”, and a worker holds one key per job for minutes — pure core first, money last, the QR very last.

For agentic workers: REQUIRED SUB-SKILL — use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps are real checkboxes. Repository: /Users/henryhudson/Programming/Main/henceforth-club (work directly on main, commit per task; every push deploys production in ~30 seconds — nothing in tasks 1–9 renders a payable QR, and task 10’s gate holds the QR until the review and the manual end-to-end pass). Tasks 6–9 build worker modules that also run under vitest; only the launchd install step (task 10) needs the Mac mini itself.

Goal: a visitor with no app uploads their own X export at henceforth.club/text, pays a QR, and a Mac mini worker inscribes their archive on Bitcoin with ephemeral per-job custody — while /text becomes the platform-neutral home listing everyone who uploaded.

Architecture: the site (Vercel) parses, quotes, and tracks jobs in Upstash but never touches a key; the worker (Mac mini, node) polls jobs, generates one random key per job, watches the job address, and spends the visitor’s own payment as the inscription’s sole funding input, premium out to cold in the same transaction. The state machine is a pure function; every side effect wraps it thinly.

Tech stack: Next.js 16 + TypeScript (vitest), @bsv/sdk 2.x (already a dependency) for keys/transactions, Upstash Redis, WhatsOnChain for the payment watch, ARC (GorillaPool → TAAL failover) for broadcast, macOS Keychain (security command) for the worker’s wrapping key.

Global constraints

  • Spec: docs/superpowers/specs/2026-07-10-xtext-web-paid-inscription-design.html — decisions are settled: ephemeral per-job custody; price = fee + WEB_PREMIUM_SATS; auto-sweep refunds to the funding transaction’s first input address; no reward output on the web path; text-only, MAX_ARCHIVE_BYTES = 1_000_000.
  • No acronyms or initialisms in prose — comments, commit messages, page copy. Code identifiers exempt.
  • The wire paths do not move. /api/x/* is the shipped 4.46 app’s contract. New web-only endpoints go under /api/text/*; existing ones stay put.
  • Keys exist only on the worker. No task may put key material, even encrypted, in Upstash, Vercel environment, or a page. Keys are per-job random (PrivateKey.fromRandom()), never derived from a shared extended key.
  • Errors as values in the pure core: discriminated unions, no throwing for control flow. Time is a parameter — no Date.now() inside pure functions.
  • Every task ends green: npm test (vitest, full suite — 361 tests before this plan) plus the task’s named new tests. Commit per task, message ends Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>.
  • Tuning constants (one module, task 4): WEB_PREMIUM_SATS (set from the day’s rate, ≈ £1), QUOTE_EXPIRY_MINUTES = 15, MAX_CONCURRENT_JOBS = 4, MAX_ARCHIVE_BYTES = 1_000_000, BROADCAST_RETRIES = 3, LATE_WATCH_DAYS = 7.

Interfaces: produces the shared types every worker task consumes:

export type JobState = "quoted" | "awaiting-payment" | "funded"
  | "inscribed" | "done" | "sweeping" | "swept";

export type TextJob = {
  jobId: string; handle: string; contentHash: string;
  feeSats: number; premiumSats: number; priceSats: number;
  state: JobState; createdAtMs: number; expiresAtMs: number;
  address?: string;            // written once, by the worker only
  fundingTxid?: string; fundingVout?: number; fundingSats?: number;
  payerRefundAddress?: string; inscriptionTxid?: string;
  sweepTxid?: string; failureReason?: string;
};

export type JobEvent =
  | { kind: "key-published"; address: string }
  | { kind: "payment-seen"; txid: string; vout: number; sats: number; refundAddress: string }
  | { kind: "expired"; residueSats: number } | { kind: "inscribed"; txid: string }
  | { kind: "registered" } | { kind: "broadcast-failed"; reason: string }
  | { kind: "sweep-broadcast"; txid: string } | { kind: "sweep-confirmed" };

// Total: every (state, event) pair returns a job or a refusal — never throws.
export function applyEvent(job: TextJob, event: JobEvent, nowMs: number):
  { ok: true; job: TextJob } | { ok: false; refused: string };

Task 9 · the sweep (worker, money path)

Every failure path ends with the visitor’s money back

Files: create scripts/xtext-worker/sweep.mjs, sweep.test.mjs; extend worker.mjs with the expiry scan and the late watch.

Interfaces: produces buildSweepTx({ jobKey, fundings, refundAddress, feeRate }): { hex: string; txid: string } | { ok: false; reason: "dust" } — fundings is every unspent output on the job address (an underpaid job may hold several small legs; the sweep spends them all in one transaction), one output of sum(sats) − fee; below-dust refuses and the job records failureReason: "dust" — the pound-scale quote makes this an edge, not a path. Worker: expired/broadcast-failed jobs emit sweep-broadcast then sweep-confirmed on first confirmation; expired job addresses stay watched for LATE_WATCH_DAYS, refunding stragglers; key material is deleted only at swept/done.

  • Failing tests: the sweep returns everything minus the miner fee to the refund address, a dust-level residue refuses rather than building an unbroadcastable transaction, the sweep retries on a rejected broadcast and the key survives until swept (stubbed ARC rejecting twice then accepting), a straggler payment on an expired job is swept within the late watch.
  • Implement; run the full suite; commit The sweep — refunds are automatic, keys outlive nothing but an unpaid refund.
