The planning ritual — /hh daily, /whh weekly

/whh sets the week's major events; /hh judges yesterday and plans today, writing into the shared /board/week planner; and /whh grows a per-app "state of the app" panel answering whether each app earns its users.

Implements docs/superpowers/specs/2026-06-30-hh-whh-planning-ritual-design.html (approved 2026-06-30). Execute task-by-task with superpowers:subagent-driven-development.

For agentic workers: use superpowers:subagent-driven-development. Steps are real checkboxes. Pure helpers are TDD — failing vitest first. Commit after each task. Phase 2 is gated on the App Store Connect App Analytics feed (ongoing requests registered 2026-06-30; instances backfill in ~1–2 days) — it builds and renders with a graceful "generating" state and lights up when the data lands. Phases 1 and 3 need no new data.

Decisions settled (the five open questions)

#DecisionResolution
1Evaluation anchorMajor-events-primary + impact-secondary. "Right focus?" is judged first against the week's major events, then an honest "did it matter" read.
2Done-stateSeparate. /hh writes a server-side done on a major event (rendered struck-through); the browser checkbox tick (local storage) stays the reader's own. They do not drive each other.
3TimelineHand-filled in v1. No /hh auto-logging onto the 0–24h grid this pass.
4Major-event altitudeOne-to-two milestones per day.
5App-state metricsReach / Growth / Effectiveness / Efficiency + value verdict, signals: active users · retention · crash rate · ratings.

Global constraints

  • Package manager npm; ES modules are .mjs (no "type" in package.json). New scripts match scripts/board/*.mjs.
  • Hybrid engine: deterministic facts (which milestones shipped, the day's review counts, App Analytics numbers) are ground truth; an ultracode Workflow writes judgement (the verdict, today's plan, the value verdict) and never recomputes numbers.
  • The planner is one shared object: board:week:<weekOf> (mirror content/board/weeks/<date>.json), field retro.weekPlan. Both rituals patch it and republish via scripts/board/publish-week.mjs — no redeploy.
  • weekPlan task shape: a major event is "label" or { label, start, end } or { label, done }. WeekPlanner.tsx already tolerates strings and objects; extend it for done.
  • Credentials stay in .env.local; only computed aggregates are published. App Analytics request ids are in ASC_ANALYTICS_REQ_*.
  • Git: branch + pull request; no main push, no force-push. Prose: no acronyms.
  • Two files live outside the repo: ~/.claude/commands/hh.md and ~/.claude/commands/whh.md. Editing them is part of this plan; they are not under git but are the behavioural surface.

Phase 1 — /hh writes today into the week planner no new data

Task 1 · week-plan.mjs (pure) + tests
Create: scripts/board/week-plan.mjs, scripts/board/week-plan.test.mjs

Pure, immutable patchers over a weekPlan array. weekOfFor("2026-07-02") → the Sunday of that week (reuse currentWeekDates from whh-aggregate.mjs). setDayEvents(plan, "Thu", ["Episode 8"]) replaces that day's tasks. markEventDone(plan, "Mon", "Submit Hansard v1") sets {label,done:true} on the matching event.

  • Write failing tests: weekOfFor returns the right Sunday; setDayEvents replaces only the named day; markEventDone flips one event to {label,done:true} and leaves others untouched; both return new arrays (no mutation).
  • Implement the three pure functions.
  • npx vitest run scripts/board/week-plan.test.mjs green; commit.
Task 2 · hh-plan-update.mjs (the I/O hook)
Create: scripts/board/hh-plan-update.mjs · uses week-plan.mjs, @upstash/redis, publish-week.mjs path

Invoked by /hh as node --env-file=.env.local scripts/board/hh-plan-update.mjs <today> <eventsJson>. Loads board:week:<weekOf> (Upstash, file fallback), applies setDayEvents for today's weekday + any markEventDone, writes weeks/<weekOf>.json, republishes.

  • Accept today's date + a small JSON payload { events:[…], done:[…] } (the agent's plan for today, from the /hh synthesis).
  • Load the current week artifact; if none exists for this week, start from weekPlanSkeleton(today).
  • Apply via week-plan.mjs; write the file; republish to Upstash.
  • Manual verify against the live week: run it with a throwaway payload, confirm /board/week shows the change; commit.
Task 3 · /hh command — judge yesterday + plan today
Edit: ~/.claude/commands/hh.md

Append a step after the morning report (step 6/7): a short Workflow that (a) judges yesterday — was the code good (from today's adjudication counts) and was it the right focus (did yesterday's shipped work advance one of the week's major events, read from board:week)? — and (b) plans today — one-to-two major events for today, grounded in that verdict + the week's remaining events + each repo's backlog. Then call hh-plan-update.mjs with the result and mark shipped milestones done.

  • Add the step text: the verdict (anchor = major-events-primary + impact-secondary), the today-plan (altitude = 1–2 events), the hh-plan-update.mjs call, and "adjust the days ahead only if the week genuinely moved".
  • Keep it read-only on the board and source; it writes only the week planner + republishes.
  • Note the boundary: the morning report (/board/report) stays the day's full digest; the week planner (/board/week) gets today's major events. No duplication of intent.
