Reddit for transaction ids — the build

From the settled spec (docs/superpowers/specs/2026-08-26-folklore-txid-board-design.html). Paste a target id; one board row; comments and Elo on that id; a user-signed ten-pence stamp; daily kudos pay. Henry's go 2026-08-26: keep the floor, Henceforth signs first, synthetic Treechat fixtures until a live post is pinned.

For agentic workers: REQUIRED: superpowers:subagent-driven-development (recommended) or superpowers:executing-plans, task by task. Real checkboxes. Each task's implementer sees only their task — the Interfaces block is how neighbouring names reach you.

Goal: a visitor can paste a Bitcoin transaction id, pay the ten-pence stamp from Henceforth, see the row on /folklore, open /folklore/tx/<target> (Twetch, Treechat, archive, or opaque), take Elo taps, and have kudos settle once a day.

Architecture: two identifiers — target (the listed transaction) and stamp (the folklore JSON plus revenue output the user broadcasts). The site never holds a key. The index is an opinion: POST /api/folklore/index verifies the stamp on chain then addLinkToBoard(target, record). The reader tries Magic Attribute Protocol, then SocialArchive, then a folklore record. The retired fifteen-second worker stays dead.

Tech stack: Next.js App Router, TypeScript strict, Vitest (npx vitest run), Henceforth Swift (stamp builder). Site gate: vitest + npm run build.

Spec: docs/superpowers/specs/2026-08-26-folklore-txid-board-design.html.

Global constraints

  • FOLKLORE_SUBMIT_ENABLED stays unset in production until the funded stamp end-to-end (spec §9).
  • Do not revive club.henceforth.xtext-worker.
