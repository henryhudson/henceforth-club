Bounty routing

Two tasks. A pure function that reads the owner’s payout address out of the archived timeline, and the one line that points the reward at it. No new files, no website change.

For agentic workers: REQUIRED SUB-SKILL — use superpowers:executing-plans or superpowers:subagent-driven-development. Steps are real checkboxes. NOTE: this repository builds with Xcode, so a subagent that cannot run xcodebuild should stop at the pure-function task; the controller runs the build and the wiring inline.

Goal: when xtext broadcasts an archive, pay the reward to the address the archived account committed to in its binding tweet, falling back to the developer address when there is none.

Architecture: one pure function chooses the reward output’s destination; the existing createTransaction call passes it instead of the fixed developer constant. Everything else — the reward amount, the single output, the non-custodial build — is unchanged.

Tech stack: Swift 6, Xcode 26, Swift Testing (@Test/#expect), SwiftBSV. Repository /Users/henryhudson/Programming/Main/FORTHapp; implement in an isolated worktree off origin/main.

Global constraints

  • No acronyms or initialisms in prose — comments and commit messages. Code identifiers and proper nouns are exempt.
  • The binding prefix is one shared constant. The parser must key on the exact string spec C uses — Verifying my Henceforth identity: — and must not introduce a second copy that could drift from the claim path.
  • A malformed or fabricated address must never reach the transaction builder. Validate every candidate with Address(fromString:) (a failable initializer that rejects a bad checksum or wrong network); an invalid candidate falls through to the developer address, so a bad payee can never fail the whole broadcast.
  • The reward amount never changes. D moves the destination only. pending.rewardSats is passed exactly as before.
  • No new files (a new file needs a project.pbxproj edit, which this work avoids). The function lives in xtextWord.swift; the tests in the existing XArchiveWiring_Tests.swift.
  • Build + test on an iOS 26 simulator (the app’s deployment target is iOS 26.0): xcodebuild test -project FORTH/FORTH.xcodeproj -scheme FORTH -sdk iphonesimulator -destination 'platform=iOS Simulator,id=<an iOS 26 device id>' -only-testing:Henceforth_Tests/XArchiveWiring_Tests.

    /// The address the archived account committed to in its binding tweet, or the
/// developer address when the timeline carries none. This is spec D: the reward
/// output's destination. Reads the WHOLE timeline (not only the newly-inscribed
/// delta) because the binding tweet may have been inscribed in an earlier
/// archive. Every candidate is validated as a real mainnet address, so a
/// fabricated or malformed binding line falls through to the developer rather
/// than producing a payee that would fail the broadcast. On a key rotation with
/// two binding lines, the last valid one in post order wins.
static func rewardPayeeAddress(
    posts: [SocialArchive.SocialPost],
    developerAddress: String,
) -> String {
    let prefix = "Verifying my Henceforth identity: "
    var routed: String?
    for post in posts {
        guard let start = post.text.range(of: prefix)?.upperBound else { continue }
        // The address is the first whitespace-delimited token after the prefix.
        guard let token = post.text[start...]
            .split(whereSeparator: { $0 == " " || $0 == "\n" }).first else { continue }
        let candidate = String(token)
        if Address(fromString: candidate) != nil { routed = candidate }
    }
    return routed ?? developerAddress
}
