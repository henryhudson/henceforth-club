Provenance — a modernised brand page at /provenance

Design spec · 2026-06-17 · henceforth.club. An unlisted, standalone modernisation of provenance.co.uk (a B2B fresh-produce supplier), built as a new route inside the henceforth-club Next.js repo and reachable only by typing the URL. Goal: modernise the design/brand — dark-purple field, emerald accent, professional (non-mono) type. Palette validated by a 16-agent judge panel (brand · accessibility · cohesion) and the contrast figures below were re-computed independently. Spec only; the build is its own plan.

This does not touch the live site. provenance.co.uk stays on its WordPress/Elementor host untouched — there is no migration, no DNS change, no SEO/redirect work. This is a developer-edited concept/showcase living quietly at henceforth.club/provenance: not in the nav, not in the sitemap, noindex. X/search never surface it; you hand the URL to whoever you want to see it.

Context — what exists today

  • The live site (provenance.co.uk) is WordPress + Elementor on LiteSpeed — a single-page B2B brochure for Provenance Partners Limited, a vertically-integrated supplier of globally-sourced exotic vegetables to UK retailers, processors and food-service, founded 2011. Sections: About · Values & Expertise · Products · Accreditations · Suppliers · Contact · a Modern Slavery statement. Sole contact: hello@provenance.co.uk. There is no repo for it; the design lives in a database as page-builder JSON.
  • The host (henceforth-club) is the style/tech guide: Next.js 16 (App Router, Turbopack), React 19, Tailwind v4 via @theme inline in globals.css (no config file), TypeScript strict, Motion for animation, npm, Vercel (push to main auto-deploys). Dark-only "Phosphor Noir" aesthetic, Space Mono everywhere.
  • The proven theming mechanism to mirror is .paper (globals.css ~lines 107–126): a scoped wrapper class that overrides --background/--foreground/--card-bg/--card-border/--card-border-hover/--muted on a route subtree, plus a body:has(.paper) overscroll rule and a scoped ::selection. Applied via a one-line wrapper in src/app/articles/layout.tsx. /articles already proves a non-dark, re-skinned route can live inside this site without drift.
  • Unlisted-route precedent already exists: /hello-world and /scriptedsupply are reachable only by URL — absent from Navbar.tsx and from app/sitemap.ts. We follow the same pattern and add robots: { index:false } on top.
  • Reusable patterns we build on: FadeIn (Motion scroll reveal), .section-line (gradient divider), .card-glow (hover border glow, reads --accent-glow), .hero-gradient/.hero-grid (background), rounded-2xl bordered cards.

Decisions locked (with Henry, this session)

D1 — Scope: unlisted standalone page, single long scroll

One route, /provenance, as a single long landing page with anchored sections (Hero → About → Values & Expertise → Products → Accreditations → Suppliers → Contact). Rejected: a multi-page section with a SectionNav sub-nav (more files, unwarranted for content that rarely changes and is developer-edited).

D2 — Standalone chrome (suppress the henceforth.club nav/footer)

The root layout wraps every page in henceforth.club's navbar (Henceforth / Deck of Cards / Hansard …) and footer. On /provenance only, that global chrome is suppressed so the page reads as a standalone Provenance brand site, not a sub-page of a dev portfolio — with a single discreet ↩ henceforth.club backlink in the page's own footer. Implemented by a pathname.startsWith('/provenance') guard in the client chrome components (see Architecture).

D3 — Content: the real Provenance content, modernised

Use the actual company copy, values, product range, accreditations and contact details (extracted from the live site), with tightened wording. The eight live "value pillars" are trimmed to six — the live wall-of-virtues reads as B2B boilerplate; fewer, stronger cards with more air read more premium. Contact is a mailto: button to hello@provenance.co.uk (matching the existing /contact page) — no form, no backend.

D4 — Visual direction: "Quiet Plum, lifted" — dark aubergine + emerald, no mono

Dark purple is the brand colour; emerald green is the accent. From the judge panel's winning "Quiet Plum" direction, with its two consensus weaknesses fixed: (1) the field is lifted so the purple is actually perceptible (the winner's plum measured 1.38:1 — invisible), and (2) henceforth.club's "developer-tool tells" are stripped for this route. Per Henry: no Space Mono — "professional, not codie." Editorial serif headlines + clean humanist sans body. Crisp emerald accent for freshness.

Two-green trap: the site's existing --accent-green is Hansard's #3da87a. The scope also sets --accent-green:#34d17a + --accent-green-glow, so any component using card-glow-green/text-accent-green inside /provenance renders the emerald, not Hansard's green.

Typography no mono

Space Mono is dropped for this route. Headlines in an editorial serif (recommended: Fraunces — modern, optical-sized, premium-food register); body and labels in a clean humanist sans (recommended: Inter). Both loaded via next/font/google in the provenance layout and exposed as CSS vars; the .provenance scope repoints --font-serif/--font-sans so Tailwind's font-serif/font-sans utilities resolve to them inside the subtree only (the rest of the site stays Space Mono). Font names are swappable at spec-review.

De-tech adjustments (the panel's consensus subtractions)

  • Drop the hero-grid lines for this route (strongest "SaaS dashboard" tell).
  • Disable the global noise overlay on this route (body:has(.provenance)::before{display:none}).
  • No glow on the headline — colour carries the accent; glow reads neon/tech.
  • Keep the hero radial, recoloured to the lifted plum so the field reads aubergine, not black. No scanlines (they're opt-in per element — simply never applied here).

Scoped CSS — appended to globals.css (~18–22 lines, additive)

.provenance {
  --background:#1e1526; --foreground:#ece8ef; --muted:#a294a8;
  --card-bg:#271a30; --card-border:#3a2844; --card-border-hover:#5a3d68;
  --accent:#34d17a; --accent-glow:rgba(52,209,122,0.16);
  --accent-green:#34d17a; --accent-green-glow:rgba(52,209,122,0.16);
  --brand-purple:#5a3d68;
  --font-serif: var(--font-fraunces), Georgia, serif;
  --font-sans:  var(--font-inter), system-ui, sans-serif;
}
body:has(.provenance){ background:#1e1526; }
body:has(.provenance)::before{ display:none; }            /* kill global noise */
.provenance ::selection{ background:rgba(52,209,122,0.22); color:#ece8ef; }  /* base ::selection hardcodes cyan */
.provenance .hero-gradient{ background:radial-gradient(ellipse 80% 50% at 50% -20%, var(--brand-purple) 0%, transparent 100%); }
/* hero-grid deliberately NOT reused on this route (dropped). */

Why these specific overrides: the cohesion lens verified that ::selection and the hero-gradient/hero-grid rules hard-code cyan/amber literals and do not read tokens — so a pure var-swap leaks cyan. They must be scoped, and the hero gradient must be .provenance-prefixed (editing the shared rule would bleed plum onto the homepage). No input:focus override is needed because the page has no form fields (mailto only).

Acceptance criteria

  1. /provenance renders the seven sections with the real, modernised content; the henceforth.club navbar and footer do not appear; the ↩ henceforth.club backlink does.
  2. The page reads as dark aubergine with an emerald accent — purple is perceptibly present (not "black with green"), headlines are serif (no monospace anywhere on the route).
  3. The [ Talk to us ] CTA opens an email to hello@provenance.co.uk; View the range scrolls to #products.
  4. Unlisted-stays-unlisted: /provenance is absent from Navbar links and from sitemap.ts; its metadata.robots.index === false.
  5. No cyan leaks: text selection and the hero gradient render emerald/plum, not cyan; the homepage hero is visually unchanged after the gradient override.
  6. npm run build is clean; accreditation logos have alt text; contrast meets WCAG AA (already computed: foreground 14.6:1, emerald-on-field 8.9:1, dark-on-emerald CTA 8.7:1).

Non-goals (out of scope)

  • Touching the live provenance.co.uk — no WordPress changes, no DNS, no redirects, no SEO migration. This is a separate unlisted page.
  • A CMS, contact form/backend, or any dynamic data. Developer-edited static content only.
  • Produce photography, multi-page sub-routes, or a SectionNav — deferred / rejected.
  • Linking to /provenance from anywhere on henceforth.club, or adding it to the sitemap.
