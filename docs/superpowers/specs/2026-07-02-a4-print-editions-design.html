Design spec · 2026-07-02 · Morning Board

A4 print editions

Every daily and weekly report edition becomes a real, archived A4 document — laid out by a print stylesheet, rendered to PDF at publish time by the Chrome on Henry's Mac, stored in Vercel Blob, and downloadable behind the board gate.

Why

Henry (2026-07-02): the daily report should sit on one A4 page like the This Week in Parliament articles; the weekly can use small type but must be printable — "make them a pdf then they will be constrained?". The mechanism answer: a PDF cannot contain live HTML, but HTML is the source format for PDFs — a print stylesheet (@page { size: A4 }) constrains the page, and a browser engine freezes it into the file. The A4 discipline lives in CSS; the PDF is the frozen output.

Decision 1 — generation happens at publish time, on the Mac. Not in a serverless function. A puppeteer script beside the publish scripts drives the locally installed Chrome, renders the just-published edition pages, and uploads the PDFs. Zero serverless weight, no cold starts, and every edition accumulates as a real file — the article archive feel. (Chosen over on-demand Vercel Chromium, ~50 MB function + cold starts.)
Decision 2 — storage is Vercel Blob, served only through gated routes. Fixed pathnames (board-pdfs/daily-<date>.pdf, board-pdfs/week-<date>.pdf), overwritten on re-render. Blob URLs are never exposed — download routes under /board (already cookie-gated) stream the bytes. Upstash was rejected for this: its ~1 MB request ceiling is too tight for embedded-font PDFs. One manual step for Henry: enable Blob on the Vercel project and re-run vercel env pull so BLOB_READ_WRITE_TOKEN lands in .env.local.
Decision 3 — page budgets. The daily prints as strictly one A4 page: emergencies → plan → cadence → verdict lines, in article typography; the "Full verdicts" fold, navigation, and buttons are excluded from print. The weekly prints in small type (~9.5px), targets one page, and may run to a second on a heavy week — page-break rules keep sections whole. The render script enforces the daily budget: it fails loudly if the daily PDF exceeds one page.

1 · The print stylesheet (the A4 form itself)

Both edition pages (/board/reports/[date], /board/reports/week/[date]) gain print rules — global (globals.css print section) plus per-page classes:

  • @page { size: A4; margin: 12mm }; body switches to print-friendly colours (dark-on-light — the site is dark-mode-only on screen, so print inverts to ink-on-paper).
  • Article typography echoing the This Week editions: compact serif headings, tight leading, rules between sections.
  • @media print hides: the site navigation, the peer links, all buttons, the daily page's <details> fold, and the index/archive chrome. The weekly's fold detail is also excluded — print carries the high-level brief only, per "high level actions and plan".
  • break-inside: avoid on each section; the weekly gets a ~9.5px base with two-column treatment for its accomplished-vs-planned list if needed to hold one page.
  • Bonus by construction: Cmd+P on either page yields the identical A4 result with no PDF pipeline involved.

2 · The render script — scripts/board/render-pdf.mjs

  • Engine: puppeteer-core launching the installed Chrome (channel: "chrome"); no bundled browser download.
  • Auth: mints its own board_session cookie from BOARD_COOKIE_SECRET in .env.local — a ~15-line node-crypto mirror of createSession in src/lib/board-auth.ts (HMAC-SHA256 over a base64url {exp} payload). No password stored anywhere.
  • Render: loads the live edition URL (https://www.henceforth.club/board/reports/… — publish precedes render, so the data is already live), waits for network idle, page.pdf({ format: "A4", preferCSSPageSize: true, printBackground: true }).
  • Budget check: parses the page count (pdf-lib); a daily over 1 page or a weekly over 2 exits non-zero with a clear message — the constraint is enforced, not hoped for.
  • Upload: @vercel/blob put() with addRandomSuffix: false, allowOverwrite: true, access: "public" (the unguessable blob host URL is never surfaced; the gated route is the only reader), contentType: "application/pdf".
  • Modes: render-pdf.mjs daily <date> · week <weekOf> · --all (backfill every date in board:report:dates + every week in board:weeks).
  • Callers: /hh after its Upstash publish renders today's daily AND the current week (the planner's done-marks change daily); /whh renders the fresh weekly. Command docs updated accordingly. One-time backfill run at ship time.

3 · Download routes + buttons

  • src/app/board/reports/[date]/pdf/route.ts and src/app/board/reports/week/[date]/pdf/route.ts — GET, safe (read-only), already behind the cookie middleware. Validate the date segment (same regex guard as the pages), look up the fixed blob path, stream with Content-Disposition: inline; filename="henceforth-daily-2026-07-02.pdf" (weekly: henceforth-week-<weekOf>.pdf). Absent blob → 404 JSON { error: "Not rendered yet — the next /hh run creates it." }.
  • A small PDF button on each edition page (hidden in print) and a pdf chip on each Reports-index row linking the route.

Verification

  • Pure helpers (blob pathname / download filename builders) unit-tested with vitest.
  • The render script's page-budget check is the standing assertion of the A4 constraint; the backfill run is its first full exercise.
  • Definition of done: (1) Cmd+P on today's daily shows one clean A4 page, article-styled, no navigation or fold; (2) the backfill renders all existing dailies + the current week without a budget failure; (3) the PDF button on today's edition downloads a correctly named file behind the gate; (4) a never-rendered date 404s with the friendly message; (5) build + suite green.

Deliberately out of scope

  • On-demand serverless Chromium.
  • Re-rendering historical editions whose data has not changed (the backfill is once; /hh re-renders only what it republishes).
  • Print styles for any page other than the two editions.
  • Public (ungated) PDF links.
