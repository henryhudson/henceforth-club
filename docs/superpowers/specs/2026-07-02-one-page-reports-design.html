Design spec · 2026-07-02 · Morning Board

One-page reports + dated Done ledger

The daily and weekly report pages become single-page briefs — high-level actions and the plan, seen all at once — and every board card carries timestamps so the Done page reads as a chronological record of accomplishment, identical on the website and the local viewer.

Why

Henry (2026-07-02): the current /board/report is clunky — long, sectioned, scroll-heavy. Like the This Week in Parliament one-page editions (pull requests #35/#36), each report should be one page containing just the high-level actions and the plan. Separately, the week planner incident this morning (Wednesday's accomplishments briefly erased by an unmarked roll) showed the deeper want: seeing what was accomplished, when. The kanban board and its Done page should mirror each other, with timestamps.

Decision 1 — location. The board area gets three peer sections, all behind the board_session gate: the kanban board (/board), the weekly schedule (/board/week, planner grid only), and a new Reports section (/board/reports) housing the one-page editions — daily /hh briefs and weekly /whh briefs together, newest first. No local HTML report artifact returns. (Henry, 2026-07-02: “keeping the weekly schedule and kanban board, then we are going to have a reports section as well.”)
Decision 2 — content. Each page shows actions + plan + cadence + a one-line verdict per app. The full per-app adjudication detail (evidence, falsifications, recommendations) stays on the page but inside a collapsed fold — one tap to expand, invisible otherwise. Nothing is lost; nothing clutters.
Decision 3 — timestamps. Cards gain movedAt (stamped on every column change) and doneAt (stamped on landing in Done, cleared on reopen). The Done page becomes a dated, newest-first ledger, rendered identically by the local viewer and the website board. No backfill of historical cards.

0 · Site structure — the Reports section

/board — kanban board (active columns + the dated Done ledger, §3)
/board/week — the weekly schedule only: the planner grid with its strike-through done marks (the deep weekly-review detail moves into the weekly report edition)
/board/reports — new index: one line per edition, newest first, a type chip on each — Daily (from board:report:dates) interleaved with Weekly (from board:weeks)
/board/reports/<date> — a daily one-pager (§1)
/board/reports/week/<date> — a weekly one-pager (§2)
/board/report — redirects to the newest daily edition (old links keep working)

The gated board pages cross-link as peers: Board · Week · Reports · Docs.

1 · The daily one-pager — /board/reports/<date>

Data contract unchanged. The page renders the same report JSON /hh already publishes (board:report:<date>: emergencies, appStore, apps[].findings, plan). The archive keeps rendering; the existing renderer in src/app/board/report/page.tsx is redesigned and rehomed under the Reports section.

Layout, top to bottom (one screen, edition-style):

  • Emergency band — as today, tighter. Empty state stays explicit: “Nothing on fire — clear to build.”
  • Today's plan — the existing tickable checklist (PlanChecklist.tsx, report JSON plan field) promoted to the centrepiece, directly under the emergencies.
  • Ship-cadence strip — one row per app from appStore.apps: live version · days since release · what is in review · blocker, rendered as a single compact line each.
  • Verdict line per app — one line each, computed client-side from apps[].findings verdict counts, e.g. deck @ 5a6141e — 0 defects · 2 crafts carded · 1 dismissed. No table.
  • “Full verdicts” fold — the current per-app evidence tables moved inside a collapsed <details> at the bottom. Default collapsed on every visit.

Date navigation moves to the Reports index (the picker on the page itself goes away — the index is the archive).

2 · The weekly one-pager — /board/reports/week/<date>

Sibling shape to the daily, rendered from the same board:week:<date> data /whh already writes (no new keys):

  • Week headline + sales strip at the top (existing /whh aggregate data; the sales plumbing itself is untouched).
  • Accomplished-vs-planned readout — the week's done-marked milestones per day, compact.
  • “Full week detail” fold — the deep aggregation sections collapsed below, mirroring the daily page.

/board/week itself becomes the schedule alone: WeekPlanner.tsx (behaviour unchanged — struck-through done marks per day remain the live record) plus a link to the week's report edition.

3 · Timestamps + the Done ledger

Card schema (additive, no migration)

FieldTypeWritten whenBy
movedAtISO datetime stringAny column change/hh edits to morning-board-data.js; local drags stamp their localStorage overlay
doneAtISO datetime stringCard lands in done; cleared if the card is reopenedSame writers

Both fields flow through sync-board/publish.mjs/latest.json untouched (cards are copied verbatim). The rev-based last-writer-wins reconcile is unchanged — /hh remains the owner of the data file; browser drags stay a local overlay exactly as column changes are today.

The Done page, mirrored

  • Local viewer (2026-06-20-morning-review-dashboard-kanban.html Done page) and the website board (a Done view in BoardClient.tsx) render the same thing: done cards sorted doneAt descending, each with a small date chip (date only; the datetime is kept in the data).
  • Historical cards without doneAt sort below the stamped ones, chip omitted. Completion dates already written in card descriptions stay as prose — no backfill.
  • The board's active columns and the Done ledger are thereby two views of one stamped dataset — they cannot drift.

Writer updates

  • ~/.claude/commands/hh.md — step 4 gains one rule: every column change sets movedAt (+doneAt when the move is into done; clear doneAt on reopen), alongside the existing rev bump.
  • The viewer's drag/move handlers stamp the overlay on drop and on ←/→ moves.

Delivery & verification

  • henceforth-club changes ship on a feature branch → pull request → Vercel preview eyeballed against today's real report/week JSON before merge (main auto-deploys).
  • Definition of done: (1) /board/reports lists daily and weekly editions interleaved newest-first with type chips; (2) today's and at least one older daily JSON render as the one-pager with the fold collapsed; (3) the current week renders as a weekly edition, and /board/week shows the schedule alone; (4) /board/report redirects to the newest daily; (5) a card moved to Done by /hh shows its date chip on both Done views, newest first; (6) npm run build green. Page-render behaviour is asserted by the Vercel preview walk-through (visual composition — the preview is the assertion); the pure verdict-count and edition-index helpers get unit tests.
  • The local viewer edit is verified by opening the board, dragging a card to Done, and confirming the chip + ordering.

Deliberately out of scope

  • Backfilling doneAt onto historical cards.
  • Any change to the report JSON schema, the publish pipeline, or the Upstash keys.
  • The /whh sales aggregation internals.
  • A returning local HTML report artifact.
